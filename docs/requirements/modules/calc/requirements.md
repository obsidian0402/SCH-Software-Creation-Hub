# 모듈 요구사항 명세: 계산 및 상태

## 문서 정보

- 상태: 사용자 승인 대기
- 수준: 모듈
- 모듈 ID: CALC
- 기준 시스템 개정: 1
- 작성 및 검토: Codex
- 구현 담당: Claude

## 모듈 책임

CALC 모듈은 UI 모듈로부터 계산 명령을 받아 현재 숫자 입력과 연산 상태를 관리하고, 덧셈·뺄셈·곱셈·나눗셈을 수행한다. 계산 결과의 재사용, 직전 연산 반복, 전체 초기화, 한 자리 삭제, 0으로 나누기 및 표시 범위 초과 오류의 전이와 복구도 담당한다.

CALC 모듈은 사용자 입력 장치나 화면을 직접 제어하지 않으며, UI 구현과 독립적인 계산 상태와 표시용 값을 제공한다.

## 범위

### 포함 범위

- 정수 및 소수 입력 상태 관리
- 덧셈, 뺄셈, 곱셈 및 나눗셈 수행
- 0으로 나누기 감지 및 오류 상태 생성
- 최대 입력 길이와 표시 가능 범위 검증
- 계산 결과를 첫 번째 피연산자로 사용하는 후속 계산
- 직전 연산자와 두 번째 피연산자를 사용하는 반복 계산
- 전체 계산 상태 초기화
- 현재 입력 숫자의 마지막 문자 삭제
- 연속된 연산자 입력 시 대기 연산자 교체
- 불완전한 계산 실행 입력의 안전한 처리
- 오류 상태에서 전체 초기화 또는 새 숫자 입력을 통한 복구
- 계산 상태의 메모리 내 유지 및 앱 종료 시 폐기
- UI 모듈에 제공할 현재 입력값, 결과 또는 오류 상태 생성

### 제외 범위

- 마우스 및 키보드 이벤트 수집과 명령 매핑
- 버튼, 표시 영역 및 오류 문구의 화면 렌더링
- Windows 창 생성 및 애플리케이션 패키징
- 사용자 인터페이스의 한국어 레이블 관리
- 삼각함수, 로그, 괄호 및 연산자 우선순위 계산
- 단항 음수 입력 및 부호 전환 기능
- 계산 이력 저장과 조회
- 계산 상태의 디스크 저장 또는 앱 재실행 시 복원
- 네트워크, 외부 서버, 데이터베이스 및 클라우드 연동
- Windows 이외 운영체제 지원

## 인터페이스

### 입력

CALC 모듈은 입력 장치에 직접 의존하지 않고 UI가 변환한 다음 계산 명령을 받는다.

- 숫자 입력: `0`부터 `9`까지의 숫자 한 자리
- 소수점 입력
- 연산자 입력: 덧셈, 뺄셈, 곱셈 또는 나눗셈
- 계산 실행
- 전체 초기화
- 한 자리 지우기

명령 인터페이스에는 마우스 버튼, 키보드 키 또는 화면 표시 기호와 같은 UI 세부 구현을 포함하지 않는다.

### 출력

모듈은 각 명령 처리 후 UI가 단일 표시 영역을 갱신할 수 있도록 다음 정보를 포함하는 현재 계산 상태를 제공한다.

- 표시 종류: 초기, 입력 중, 결과 또는 오류
- 표시용 현재 입력값 또는 계산 결과
- 오류 상태일 때 표시할 값 `오류`
- 다음 명령을 처리하는 데 필요한 계산 상태
- 대기 중인 연산자 존재 여부

내부 피연산자와 반복 연산 정보는 UI가 직접 수정할 수 없는 모듈 소유 상태로 관리한다.

### 의존 모듈

- CALC 모듈은 UI 모듈이나 다른 제품 모듈에 의존하지 않는다.
- UI 모듈이 CALC 모듈의 명령 입력 및 상태 출력 인터페이스에 의존한다.
- 의존 방향은 `UI → CALC`이며 순환 의존을 허용하지 않는다.
- CALC 모듈은 네트워크, 외부 서버, 데이터베이스 또는 영구 저장소에 의존하지 않는다.

## 정상 흐름

1. CALC 모듈이 현재 입력, 연산자, 반복 연산 및 오류 정보가 없는 초기 상태로 생성된다.
2. UI가 사용자의 숫자 입력을 CALC 숫자 입력 명령으로 전달한다.
3. CALC가 숫자와 소수점을 현재 입력값으로 구성하여 입력 중 상태를 반환한다.
4. UI가 사칙연산자 하나를 전달한다.
5. CALC가 현재 입력값을 첫 번째 피연산자로 확정하고 연산자를 대기 상태로 저장한다.
6. UI가 두 번째 숫자를 전달한다.
7. CALC가 두 번째 피연산자를 구성한다.
8. UI가 계산 실행 명령을 전달한다.
9. CALC가 선택된 이항 연산을 수행하고 결과 상태를 반환한다.
10. 결과 상태에서 다음 중 하나로 진행한다.
    - 연산자와 새 피연산자를 받아 직전 결과에 이어 계산한다.
    - 계산 실행 명령을 다시 받아 직전 연산과 두 번째 피연산자를 반복 적용한다.
    - 새 숫자 입력을 받아 새 계산 입력을 시작한다.
    - 전체 초기화 명령을 받아 초기 상태로 돌아간다.

## 예외 및 오류 흐름

- 나눗셈의 두 번째 피연산자가 0이면 CALC는 결과 대신 `오류` 상태를 반환하며 무한대 또는 숫자가 아님 값을 노출하지 않는다.
- 오류 상태에서 새 숫자를 받으면 이전 상태를 폐기하고 해당 숫자로 새 입력을 시작한다.
- 오류 상태에서 전체 초기화를 받으면 모든 계산 상태를 제거하고 초기 상태로 돌아간다.
- 소수점이 이미 포함된 입력에 소수점이 다시 들어오면 두 번째 소수점을 추가하지 않고 현재 입력 상태를 유지한다.
- 입력할 문자가 없는 상태에서 한 자리 지우기가 들어오면 상태를 손상하지 않고 계속 명령을 받을 수 있어야 한다.
- 두 번째 피연산자가 없는 등 계산이 불완전한 상태에서 계산 실행 명령이 들어오면 명령을 무시하고 계속 입력 가능한 상태를 유지한다.
- 두 번째 피연산자를 입력하기 전에 연산자가 연속으로 들어오면 마지막 연산자가 대기 연산자를 대체한다.
- 허용 입력 길이를 초과한 숫자 입력은 현재 입력에 추가하지 않는다.
- 표시 가능 범위를 벗어난 결과가 발생하면 정상 결과 대신 오류 상태로 전이한다.
- 예외 또는 오류 처리 후에도 CALC는 전체 초기화 또는 새 숫자 입력을 계속 처리할 수 있어야 한다.

## 데이터 영향

- CALC의 모든 상태는 앱 실행 중 메모리에만 존재한다.
- 영구 저장하거나 외부 시스템으로 전송하는 데이터는 없다.
- 앱 종료 시 현재 입력, 피연산자, 대기 연산자, 결과, 반복 연산 정보 및 오류 상태가 모두 폐기된다.
- 최소 런타임 상태는 다음 정보를 포함한다.
  - 현재 입력 문자열
  - 첫 번째 피연산자
  - 대기 중인 연산자
  - 직전 계산의 연산자
  - 직전 계산의 두 번째 피연산자
  - 현재 표시용 값
  - 현재 표시 종류
  - 오류 여부
- 숫자 입력은 계산 전에 유효한 숫자로 변환할 수 있어야 하며, 표시용 문자열과 산술용 값 사이의 변환에서 사용자의 입력 의미를 보존해야 한다.

## 테스트 관점

- 각 사칙연산을 정수, 소수 및 음수 결과 조합으로 검증한다.
- 소수점 중복 입력이 현재 입력을 손상하지 않는지 검증한다.
- 나눗셈의 두 번째 피연산자로 양의 0, 소수 표기의 0 등 계산상 0인 값을 사용해 오류 전이를 검증한다.
- 전체 초기화가 현재 입력뿐 아니라 대기 연산, 반복 연산과 오류 상태까지 제거하는지 검증한다.
- 한 자리 지우기를 정수, 소수, 한 자리 입력 및 빈 입력 상태에서 검증한다.
- 계산 결과에 이어 새로운 연산을 수행할 때 직전 결과가 첫 번째 피연산자로 사용되는지 검증한다.
- 계산 실행을 여러 번 반복할 때 직전 연산자와 두 번째 피연산자가 유지되고 결과가 누적되는지 검증한다.
- 새 계산을 시작하거나 전체 초기화를 수행한 뒤 이전 반복 연산 정보가 재사용되지 않는지 검증한다.
- 오류 상태에서 새 숫자 입력과 전체 초기화의 두 복구 경로를 각각 검증한다.
- 연산자 연속 입력 시 마지막 연산자만 적용되는지 검증한다.
- 불완전한 상태의 계산 실행과 빈 입력 삭제가 처리되지 않은 예외를 발생시키지 않는지 검증한다.
- 최대 입력 길이와 표시 범위 경계의 바로 아래, 경계, 바로 위 값을 검증한다.
- 유한 소수 및 끝나지 않는 소수의 나눗셈 결과 표시를 검증한다.
- 네트워크 차단 및 앱 재실행 상태에서 외부 의존과 상태 복원이 없는지 검증한다.
- 각 모듈 테스트 이름 또는 속성에 대응하는 `MOD-CALC-AC-###` ID를 포함한다.

## 위험 요소

- JavaScript 숫자 형식을 직접 사용하면 `0.1 + 0.2`와 같은 계산에서 사용자가 기대하지 않은 부동소수점 표현이 나타날 수 있다.
- 나눗셈 결과를 소수점 이하 5자리로 제한할 때 반올림과 버림 중 어떤 규칙을 적용하는지에 따라 결과가 달라진다.
- 최대 10자리의 산정에 소수점, 선행 0 및 결과의 음수 부호를 포함하는지가 명확하지 않다.
- 표시 가능 범위의 수치 경계가 정의되지 않아 범위 초과 오류를 일관되게 판정할 수 없다.
- 큰 정수는 표시 자릿수 제한에 도달하기 전에 JavaScript 안전 정수 범위를 초과할 수 있다.
- 결과 상태에서 연산자 없이 새 숫자를 입력했을 때 새 계산을 시작하는지에 대한 공식 요구사항이 명확하지 않다.
- 한 자리 지우기로 소수점이나 마지막 숫자를 제거한 후 표시해야 할 초기값 정책이 명확하지 않다.
- 반복 계산 도중 0으로 나누기나 표시 범위 초과가 발생했을 때 반복 연산 정보를 유지할지 폐기할지 명확하지 않다.

## 가정

- CALC는 한 번에 하나의 이항 연산만 대기시키며 괄호나 연산자 우선순위를 처리하지 않는다.
- 음수는 뺄셈의 계산 결과로만 생성되며 사용자가 단항 음수를 직접 입력하지 않는다.
- UI의 `×`와 `÷` 또는 키보드의 `*`와 `/`는 UI에서 동일한 CALC 연산자 명령으로 정규화된다.
- 키보드의 `Enter`, `C`, `Backspace` 매핑은 UI 책임이며 CALC는 각각 계산 실행, 전체 초기화, 한 자리 지우기 명령만 처리한다.
- 계산 결과는 후속 연산과 반복 계산을 위한 산술 값으로 사용할 수 있다.
- 오류 표시의 한국어 렌더링은 UI 책임이지만 CALC는 시스템 결정에 따라 표시용 오류 값 `오류`를 제공한다.
- 모듈은 사용자별 상태나 여러 계산 세션을 동시에 관리하지 않는다.
- 시스템 문서의 미결 질문 아래 기록된 사용자 답변은 모듈 요구사항 구체화를 위한 결정으로 간주한다.

9. 현재 입력이 `0`일 때 추가 숫자를 입력하면 선행 0을 유지하는가, 새 숫자로 대체하는가?
10. 오류를 발생시킨 뒤 반복 연산자와 두 번째 피연산자를 즉시 폐기해야 하는가?
11. 시스템 요구사항이 담당 모듈로 지정한 `SYS-NFR-001`, `SYS-NFR-003`, `SYS-NFR-005`, `SYS-NFR-006`은 CALC 요구사항에 반영했다. UI 전담인 `SYS-NFR-002`, `SYS-NFR-004` 및 `SYS-FR-011`부터 `SYS-FR-013`은 CALC가 직접 다루지 않는다.

## 구현 전 확인 사항

- 일반 소수 계산과 나눗셈 결과의 정밀도 및 반올림 규칙을 확정해야 한다.
- 최대 10자리의 계산 기준과 계산 결과에 적용할 표시 가능 범위를 수치로 확정해야 한다.
- 결과 상태에서 새 숫자를 입력하는 동작과 입력이 모두 삭제된 상태의 표시 정책을 확정해야 한다.
- 오류 발생 시 반복 연산 정보를 유지할지 폐기할지 확정해야 한다.
- CALC 명령과 출력 상태의 구체적인 TypeScript 인터페이스를 구현 전에 합의하되 UI 구현과 독립성을 유지해야 한다.
- UI와 CALC 사이에서 숫자 및 연산 명령을 한 번만 정규화하고 동일한 상태 전이 규칙을 사용하도록 확인해야 한다.
- 모듈 테스트는 각 인수 조건 ID를 테스트 이름 또는 속성에 포함하고 외부에서 관찰 가능한 명령 입력과 상태 출력을 기준으로 작성해야 한다.
