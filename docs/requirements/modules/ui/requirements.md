# 모듈 요구사항 명세: 데스크톱 사용자 인터페이스

## 문서 정보

- 상태: 사용자 승인 대기
- 수준: 모듈
- 모듈 ID: UI
- 기준 시스템 개정: 1
- 작성 및 검토: Codex
- 구현 담당: Claude

## 모듈 책임

UI 모듈은 단일 Windows 데스크톱 창에서 마우스와 키보드 입력을 수집하고 계산 명령으로 변환하여 CALC 모듈에 전달해야 한다. CALC 모듈이 반환한 현재 입력값, 계산 결과 또는 오류를 단일 표시 영역에 렌더링해야 한다.

UI 모듈은 계산 규칙이나 계산 상태를 직접 관리하지 않으며, 입력 장치와 CALC 명령 사이의 매핑 및 계산 상태의 화면 표시를 담당한다.

## 범위

### 포함 범위

- 단일 계산기 창과 단일 표시 영역 제공
- 숫자 `0`부터 `9`까지의 화면 버튼 제공
- 소수점, 사칙연산자, 계산 실행, 전체 초기화 및 한 자리 지우기 버튼 제공
- 화면 버튼의 마우스 선택 처리
- 키보드 숫자, 소수점, 사칙연산자, `Enter`, `C` 및 `Backspace` 입력 처리
- 마우스와 키보드 입력을 동일한 CALC 명령으로 정규화
- CALC 명령 처리 후 현재 입력값, 계산 결과 또는 오류 표시
- 오류 상태에서 전체 초기화 또는 새 숫자 입력 전달
- 한국어 버튼 명칭, 상태 안내 및 오류 표시
- Windows 10/11 데스크톱 실행
- 오프라인 동작
- 입력 후 100ms 이내 표시 갱신
- 앱 재실행 시 초기 화면 표시
- 잘못되거나 불완전한 입력 후에도 계속 사용할 수 있는 UI 제공

### 제외 범위

- 사칙연산 계산과 숫자 정밀도 처리
- 피연산자, 대기 연산자 및 반복 연산 상태 관리
- 0으로 나누기와 표시 범위 초과의 산술 판정
- 연속 연산자 교체와 불완전한 계산 실행의 상태 전이 결정
- 계산 이력 저장 및 조회
- 계산 상태의 영구 저장과 복원
- 공학용 함수, 괄호 및 연산자 우선순위 지원
- 부호 전환 버튼과 단항 음수 입력
- 다중 창과 탭
- 사용자 계정, 네트워크, 외부 서버 및 클라우드 연동
- Windows 이외 운영체제 지원

## 인터페이스

### 입력

UI 모듈은 다음 사용자 입력을 수집한다.

- 마우스 입력
  - 숫자 `0`부터 `9`까지의 버튼
  - 소수점 버튼
  - 덧셈, 뺄셈, 곱셈 및 나눗셈 버튼
  - 계산 실행 버튼
  - 전체 초기화 버튼
  - 한 자리 지우기 버튼
- 키보드 입력
  - 숫자 키 `0`부터 `9`
  - 소수점 키 `.`
  - 연산자 키 `+`, `-`, `*`, `/`
  - 계산 실행 키 `Enter`
  - 전체 초기화 키 `C`
  - 한 자리 지우기 키 `Backspace`
- CALC 모듈 출력
  - 초기 상태
  - 현재 입력 상태와 표시용 입력값
  - 결과 상태와 표시용 결과
  - 오류 상태와 표시용 오류 값

UI는 사용자 입력을 다음 CALC 명령 중 하나로 정규화한다.

- 숫자 입력
- 소수점 입력
- 덧셈, 뺄셈, 곱셈 또는 나눗셈
- 계산 실행
- 전체 초기화
- 한 자리 지우기

### 출력

UI 모듈은 단일 계산기 창에서 다음 출력을 제공한다.

- 숫자, 소수점, 사칙연산자, 계산 실행, 전체 초기화 및 한 자리 지우기 버튼
- 현재 입력값, 계산 결과 또는 오류 중 하나를 보여주는 단일 표시 영역
- CALC가 오류 상태를 반환했을 때의 한국어 문구 `오류`
- 각 사용자 입력에 대응하여 CALC에 전달하는 계산 명령

화면에는 CALC의 내부 피연산자, 반복 연산 정보 또는 구현 세부 상태를 직접 노출하지 않는다.

### 의존 모듈

- UI 모듈은 사용자 입력을 전달하고 표시 상태를 얻기 위해 CALC 모듈에 의존한다.
- UI는 CALC가 제공하는 명령 입력 및 상태 출력 인터페이스만 사용해야 한다.
- UI는 계산 결과나 오류 여부를 독자적으로 산출하지 않아야 한다.
- CALC는 UI 구현에 의존하지 않아야 한다.
- 의존 방향은 `UI → CALC`이며 순환 의존을 허용하지 않는다.
- UI는 네트워크, 외부 서버, 데이터베이스 또는 영구 저장소에 의존하지 않는다.

## 정상 흐름

1. 사용자가 앱을 실행한다.
2. UI가 단일 계산기 창과 초기 표시 상태를 제공한다.
3. 사용자가 마우스 버튼 또는 키보드로 첫 번째 수를 입력한다.
4. UI가 입력을 CALC 명령으로 변환해 전달한다.
5. UI가 CALC에서 반환된 현재 입력값을 단일 표시 영역에 표시한다.
6. 사용자가 사칙연산자를 입력한다.
7. UI가 대응하는 연산자 명령을 CALC에 전달한다.
8. 사용자가 두 번째 수를 입력한다.
9. UI가 각 입력을 CALC에 전달하고 반환된 현재 입력값을 표시한다.
10. 사용자가 화면의 계산 실행 버튼을 선택하거나 `Enter` 키를 입력한다.
11. UI가 계산 실행 명령을 CALC에 전달한다.
12. UI가 CALC에서 반환된 결과를 단일 표시 영역에 표시한다.
13. 사용자는 다음 중 하나를 수행할 수 있다.
    - 연산자와 새 피연산자를 입력하여 직전 결과에 이어 계산한다.
    - 계산 실행 버튼 또는 `Enter`를 다시 입력하여 직전 연산을 반복한다.
    - 새 숫자를 입력하여 CALC가 제공하는 새 계산 상태를 표시한다.
    - 전체 초기화를 입력하여 초기 상태로 돌아간다.

## 예외 및 오류 흐름

- CALC가 0으로 나누기 또는 표시 범위 초과 오류를 반환하면 UI는 결과 대신 `오류`를 표시하고 계속 입력을 받아야 한다.
- 오류 상태에서 전체 초기화 입력이 발생하면 UI는 이를 CALC에 전달하고 반환된 초기 상태로 오류 표시를 교체한다.
- 오류 상태에서 숫자 입력이 발생하면 UI는 이를 CALC에 전달하고 반환된 새 입력값으로 오류 표시를 교체한다.
- 사용자가 현재 숫자에 두 번째 소수점을 입력하여 CALC가 기존 상태를 반환하면 UI는 기존 입력값을 유지한다.
- 삭제할 입력 문자가 없는 상태에서 한 자리 지우기가 입력되어도 UI는 계속 응답하고 후속 입력을 받을 수 있어야 한다.
- 계산에 필요한 입력이 완성되지 않은 상태에서 계산 실행이 입력되어도 UI는 CALC가 반환한 상태를 유지하고 계속 입력을 받아야 한다.
- 연산자가 연속으로 입력되면 UI는 각 연산자 입력을 CALC에 전달하고 CALC가 반환한 상태를 표시해야 한다.
- 허용되지 않은 키보드 입력은 CALC 명령으로 변환하지 않으며 현재 표시 상태를 변경하지 않아야 한다.
- CALC 명령 처리에서 오류 상태가 반환되더라도 UI 창은 종료되거나 응답 불가 상태가 되어서는 안 된다.

## 데이터 영향

- UI가 취급하는 데이터는 사용자 입력, CALC 명령 및 표시용 상태로 한정된다.
- UI는 현재 입력값, 결과, 오류 또는 화면 상태를 디스크에 저장하지 않는다.
- UI는 계산 데이터를 네트워크나 외부 시스템으로 전송하지 않는다.
- 앱 종료 시 화면에 표시된 모든 계산 상태가 폐기된다.
- 앱 재실행 시 이전 입력, 결과 또는 오류를 복원하지 않고 초기 상태를 표시한다.
- 피연산자, 대기 중인 연산자 및 반복 계산 정보의 기준 상태는 CALC가 소유하며 UI가 별도로 복제하거나 수정하지 않는다.

## 테스트 관점

- 화면 버튼과 키보드 입력이 같은 CALC 명령 및 표시 결과를 만드는지 검증한다.
- 숫자, 소수점, 네 연산자, 계산 실행, 전체 초기화 및 한 자리 지우기의 모든 마우스 버튼을 검증한다.
- 키보드의 숫자, `.`, `+`, `-`, `*`, `/`, `Enter`, `C` 및 `Backspace` 매핑을 검증한다.
- `=` 키가 계산 실행으로 처리되지 않는지 검증한다.
- 초기, 입력 중, 결과 및 오류 상태가 동일한 단일 표시 영역에 올바르게 나타나는지 검증한다.
- 0으로 나누기에서 `Infinity`, `NaN`, 빈 화면 또는 비한국어 오류 문구가 표시되지 않는지 검증한다.
- 오류 상태에서 전체 초기화와 새 숫자 입력의 두 복구 경로를 각각 검증한다.
- 중복 소수점, 빈 입력 삭제, 불완전 계산 실행, 연속 연산자 및 지원하지 않는 키 입력 후에도 창이 계속 응답하는지 검증한다.
- 직전 결과 후속 계산과 계산 실행 반복에서 CALC가 반환한 결과가 매번 화면에 반영되는지 검증한다.
- Windows 10/11에서 창 실행, 입력 및 표시를 검증한다.
- 네트워크 차단 상태에서 모든 UI 기능이 동작하는지 검증한다.
- 앱 종료 후 표시 상태가 남지 않는지 검증한다.
- 입력 이벤트부터 화면 갱신까지 100ms 성능 기준을 대표적인 마우스 및 키보드 입력으로 측정한다.
- 각 모듈 테스트 이름 또는 속성에 대응하는 `MOD-UI-AC-###` ID를 포함한다.

## 위험 요소

- 초기 표시값이 정의되지 않아 빈 값과 `0` 중 구현 및 테스트 기대가 달라질 수 있다.
- 시스템 문서가 화면의 계산 실행 버튼은 `=`로 제시하면서 키보드의 `=` 입력은 지원하지 않도록 결정하여 입력 장치별 기호가 혼동될 수 있다.
- 전체 초기화 버튼의 표시 문구와 한 자리 지우기 버튼의 한국어 명칭 또는 기호가 확정되지 않았다.
- 최대 10자리 입력과 긴 결과가 단일 표시 영역의 너비를 초과할 수 있으나 축소, 잘림 또는 오류 표시 정책이 정의되지 않았다.
- UI가 CALC 상태를 별도로 복제하면 마우스와 키보드 입력 또는 오류 복구 과정에서 상태가 불일치할 수 있다.
- 키보드 숫자 패드의 `Enter`, 소수점 및 연산자 키를 일반 키와 동일하게 지원할지 명확하지 않다.
- 키보드 입력이 버튼 활성화 상태나 시각적 피드백으로 표현되어야 하는지 정의되지 않았다.
- Windows 배율, 창 크기 및 글꼴 차이로 버튼이나 표시값이 잘릴 수 있다.
- 100ms 기준의 측정 시작점과 화면 갱신 완료 판정 방식이 구체적으로 정의되지 않았다.

## 가정

- UI는 한 번에 하나의 계산 세션만 표시하는 단일 창 애플리케이션이다.
- 화면의 곱셈과 나눗셈 버튼에는 각각 `×`와 `÷` 기호를 사용할 수 있다.
- 화면의 계산 실행 버튼에는 `=` 기호를 사용하지만 키보드 계산 실행은 `Enter`만 지원한다.
- 전체 초기화의 키보드 입력은 대소문자와 관계없이 `C`로 처리한다.
- 한 자리 지우기의 키보드 입력은 `Backspace`로 처리한다.
- 음수는 CALC가 반환한 뺄셈 결과로만 표시되며 부호 전환 버튼은 제공하지 않는다.
- 연속 연산자 처리, 불완전 계산 실행, 최대 입력 길이 및 결과 정밀도는 CALC가 결정하고 UI는 반환 상태만 표시한다.
- CALC가 제공하는 표시용 문자열은 UI가 다시 계산하거나 숫자 형식을 변경하지 않고 표시한다.
- 오류 표시 문구는 시스템 문서에 기록된 결정에 따라 `오류`로 사용한다.
- UI의 런타임 상태는 앱 실행 중 메모리에만 존재한다.
- 시스템 문서의 미결 질문 아래 기록된 사용자 답변은 모듈 요구사항 구체화를 위한 결정으로 간주한다.

## 미결 질문

1. 초기 표시 영역에는 `0`, 빈 값 또는 다른 안내 문구 중 무엇을 표시해야 하는가?
2. 화면의 전체 초기화 버튼 명칭은 `C`, `전체 초기화` 또는 다른 한국어 문구 중 무엇인가?
3. 화면의 한 자리 지우기 버튼 명칭은 `⌫`, `지우기` 또는 다른 한국어 문구 중 무엇인가?
4. 키보드 숫자 패드의 숫자, 소수점, 사칙연산자 및 `Enter`도 일반 키와 동일하게 지원해야 하는가?
5. 키보드 입력 시 대응하는 화면 버튼에 눌림 상태 등의 시각적 피드백을 제공해야 하는가?
6. 창의 초기 크기, 최소 크기, 크기 조절 허용 여부 및 최대화 허용 여부는 무엇인가?
7. 최대 10자리 입력 또는 긴 결과가 표시 영역의 너비를 넘을 때 글자 크기 축소, 가로 스크롤, 잘림 또는 오류 중 어떤 방식을 적용해야 하는가?
8. 버튼 간 키보드 포커스 이동과 `Space` 입력을 통한 버튼 실행을 지원해야 하는가?
9. 사용자 접근성을 위해 필요한 최소 글자 크기, 색 대비, 포커스 표시 및 스크린 리더 레이블 기준은 무엇인가?
10. 100ms 응답시간은 키 입력 또는 마우스 이벤트 발생 시점부터 어떤 화면 갱신 완료 시점까지 측정해야 하는가?
11. CALC가 예상하지 못한 처리 실패를 반환하거나 호출 자체가 실패한 경우에도 `오류`로 표시할지 별도의 오류 정책을 사용할지 정해야 하는가?
12. 담당 시스템 기능 요구사항 `SYS-FR-001`부터 `SYS-FR-014`는 모두 UI 요구사항에 반영했다. UI가 구현 모듈로 지정된 `SYS-NFR-001`부터 `SYS-NFR-006`도 모두 비기능 요구사항에 반영했으며, UI에서 다루지 않은 담당 시스템 요구사항은 없다.

## 구현 전 확인 사항

- 초기 표시값과 전체 초기화 및 한 자리 지우기 버튼의 화면 명칭을 확정해야 한다.
- 숫자 패드 지원 범위와 키보드 입력의 시각적 피드백 여부를 확정해야 한다.
- 창 크기, 크기 조절 정책 및 긴 표시값의 렌더링 방식을 확정해야 한다.
- 최소 접근성 기준과 키보드 포커스 이동 범위를 확정해야 한다.
- 100ms 응답시간의 측정 시작점과 화면 갱신 완료 판정 방식을 확정해야 한다.
- UI와 CALC 사이의 명령 및 상태 TypeScript 인터페이스를 합의하고 의존 방향 `UI → CALC`를 유지해야 한다.
- UI는 CALC가 제공한 표시용 상태를 단일 기준으로 사용하고 계산 규칙이나 상태를 중복 구현하지 않아야 한다.
- 모듈 테스트는 각 인수 조건 ID를 테스트 이름 또는 속성에 포함하고 외부에서 관찰 가능한 입력 및 화면 출력을 기준으로 작성해야 한다.
