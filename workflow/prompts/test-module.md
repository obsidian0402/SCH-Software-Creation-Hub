# 수행 작업

1. `workflow/rules/codex.md`를 읽는다.
2. 모듈 요구사항 문서의 모든 `MOD-{{MODULE_UPPER}}-FR`, `-NFR`, `-AC` ID를 수집한다.
3. 기존 테스트를 확인한다.
4. 요구사항과 테스트 사이의 추적 관계를 확인한다.
5. 누락된 테스트를 작성한다. 테스트 이름에 AC ID를 넣는다.
6. 요구사항과 맞지 않거나 오래된 테스트를 수정한다.
7. 지정된 테스트 명령을 실행한다.
8. 요구사항 및 인수 조건별 통과 여부를 판정한다.
9. 보고서를 작성한다.

# 테스트 성격

모듈 테스트는 구현 세부사항이 아니라 다음을 검증한다.

- 모듈 기능 요구사항
- 모듈 비기능 요구사항
- 모듈 인수 조건
- 정상 사용자 흐름
- 예외 및 오류 흐름
- 모듈 외부에서 관찰 가능한 결과

Claude 소유의 단위 테스트와 성격을 섞지 않는다. 내부 함수 호출 검증이나
private 상태 확인은 단위 테스트의 몫이다.

- 제품 코드 수정
- 단위 테스트 수정
- 요구사항 문서 수정
- `workflow/` 수정
- 다른 모듈의 테스트 수정
- 시스템 테스트 수정
- git 커밋 또는 브랜치 변경
- 실패한 테스트 삭제, 비활성화, 건너뛰기
- 현재 제품 동작에 맞춰 기대값을 낮추는 행위
- 요구사항을 임의로 재해석해 통과시키는 행위

제품 코드 문제를 발견해도 직접 고치지 않는다. 보고만 한다.

# 실패 분류

반드시 다음 중 하나로 판정한다.

- `PRODUCT_CODE_BUG` 요구사항과 테스트가 정확하고 환경도 정상인데 제품 동작이 다름
- `TEST_OR_REQUIREMENT_SUSPECT` 테스트나 요구사항 쪽이 의심되거나 판단 불가
- `BLOCKED_ENVIRONMENT` 테스트 명령 자체를 실행할 수 없음
