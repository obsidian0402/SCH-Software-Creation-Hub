# 필수 수행 작업

1. `workflow/rules/codex.md`를 읽는다.
2. 상위 시스템 요구사항 문서를 읽는다.
3. 이 모듈이 담당하는 `SYS-FR`, `SYS-NFR`, `SYS-AC` ID를 모두 수집한다.
4. 관련 제품 코드를 읽는다.
5. 모듈 기능 요구사항과 비기능 요구사항을 작성한다.
6. 각 요구사항에 상위 시스템 요구사항 ID를 연결한다.
7. 모듈의 인터페이스(입력, 출력, 의존)를 정의한다.
8. 정상 흐름과 예외 흐름을 작성한다.
9. 각 요구사항에 연결된 인수 조건을 작성한다.
10. 불명확한 사항은 미결 질문으로 남긴다.

# 추적성 의무 (중요)

- **모든 모듈 요구사항은 `상위` 열에 시스템 요구사항 ID를 하나 이상 기록한다.**
  비어 있으면 고아로 판정되어 검증이 실패한다.
- 담당 시스템 요구사항 중 이 모듈에서 다루지 않는 것이 있으면 그 이유를
  `미결 질문`에 적는다.
- 상위 시스템 요구사항과 모순되는 모듈 요구사항을 쓰지 않는다. 모순이 필요해
  보이면 작성을 멈추고 `미결 질문`에 기록한다.

# 금지 사항

- 제품 코드 수정 금지
- 테스트 수정 금지
- 시스템 요구사항 문서 수정 금지
- 다른 모듈의 요구사항 수정 금지
- `workflow/` 수정 금지
- git 커밋 또는 브랜치 변경 금지
- 구현 코드 작성 금지
- 테스트 실행 금지

# ID 규칙

| 종류 | 형식 |
|---|---|
| 기능 요구사항 | `MOD-{{MODULE_UPPER}}-FR-001` |
| 비기능 요구사항 | `MOD-{{MODULE_UPPER}}-NFR-001` |
| 인수 조건 | `MOD-{{MODULE_UPPER}}-AC-001` |

일련번호는 세 자리로 고정한다. 기존 요구사항을 수정할 때는 의미가 유지되는
ID를 보존한다.

# 표 형식 준수 (중요)

추적성 파서가 표의 **헤더 이름**으로 열을 찾는다. 아래 헤더를 글자 그대로
사용한다. 열 순서는 바꿔도 되지만 헤더 문구는 바꾸면 안 된다.
