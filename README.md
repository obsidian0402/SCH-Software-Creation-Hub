## 이 문서를 왜 채워야 하는가

`/requirements system` 이 실행되면 Codex 는 이 파일을 읽는다. 프로젝트 맥락을
얻을 수 있는 거의 유일한 창구다. 비어 있으면 Codex 는 다음 중 하나를 한다.

- 미결 질문만 잔뜩 남긴 빈약한 요구사항을 쓴다
- 그럴듯하게 지어낸다 (더 나쁘다)
- 스택에 맞지 않는 모듈 분해를 제안한다

멋진 문서일 필요는 없다. **Codex 가 코드에서 추론할 수 없는 사실**만 있으면
된다. 아래 6개 절, 15~30줄이면 충분하다.

작성 후 이 절도 삭제한다.

- 테스트: Vitest (unit, module) + Playwright (system)

디렉터리 구조

    src/core       순수 TypeScript. electron 을 import 하지 않는다
    src/main       창 생성, IPC 배선, OS 연동만
    src/preload    contextBridge 노출만
    src/renderer   React
    src/shared     IPC 채널 정의와 공용 타입

비즈니스 로직은 전부 `src/core` 에 둔다. 상세 규칙은
`workflow/rules/claude.md` 2절에 있다.

## 개발 워크플로

이 프로젝트는 요구사항·제품 디자인·모듈/시스템 테스트를 Codex 가, 제품 코드

- 프레임워크 사용법: `workflow/README.md`
- Codex 규칙: `workflow/rules/codex.md`
- Claude 규칙: `workflow/rules/claude.md`

시작하기

    pwsh -NoProfile -File workflow/scripts/init-workspace.ps1
    pwsh -NoProfile -File workflow/scripts/install-skills.ps1

    /requirements system "<전체 프로그램 요청>"
